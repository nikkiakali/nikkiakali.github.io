Pocket-LLM

Tiny GPT-style language model built from scratch to make transformer internals, tokenization, training, and inference concrete through implementation rather than abstraction.

System Overview

Learning the Stack by Building the Stack

Pocket-LLM is a compact GPT-style language model implementation built from first principles. Rather than treating large language models as black-box APIs, the project rebuilds the full loop directly in code: tokenization, model definition, training, checkpointing, and inference.

The system supports both character-level and BPE-based workflows, enabling direct comparison between simpler baselines and more practical tokenization strategies. The result is not just a toy model, but a controlled environment for understanding how model architecture, tokenizer choice, data scale, and runtime constraints interact.

Implementation

What the Project Actually Includes

Custom Tokenization Paths

The repository supports both character-level tokenization and BPE-based tokenization. This makes it possible to study how vocabulary granularity affects compression, sample quality, and training behavior across small model sizes.

Modular Model Code

Core components are separated into focused modules for tokenizers, model definition, training, and inference. That structure makes the implementation easier to reason about, extend, and test without turning the project into a monolith.

Config-Driven Training

YAML-based configs define training runs such as small_bpe, tiny_bpe, and tiny_char. This keeps experimentation reproducible and makes model-size or tokenizer changes easier to compare systematically.

Engineering Challenges

Tradeoffs Beneath the Surface

Simplicity vs. Fidelity

Building a model from scratch is valuable only if the implementation remains understandable. A central challenge was keeping the code compact enough for learning while still preserving the essential mechanics of modern autoregressive transformers.

Tokenization Strategy

Character-level models are conceptually simple but inefficient, while BPE adds complexity in exchange for better token efficiency and output quality. Supporting both paths made the tradeoff visible rather than theoretical.

Resource Constraints

The project was designed to be CPU-friendly for fast experimentation, but also flexible enough to scale to better quality runs when more compute is available. That required deliberate choices around model size, configs, and training workflow.

Design Principles

How the Project Was Shaped

Learn by Rebuilding

The fastest way to internalize model behavior is to implement the components directly. Tokenization, attention, training loops, and sampling become much clearer when each layer is explicit and debuggable.

Optimize for Understanding

The project favors clarity of system boundaries over unnecessary abstraction. The goal is not to mimic a production framework, but to make each stage of the model lifecycle visible and inspectable.

Make Experimentation Cheap

Small, configurable runs reduce friction. When it is easy to swap configs, tokenizer choices, or checkpoints, iteration becomes fast enough to support real intuition rather than one-off experiments.

Outcome

Why This Project Matters

Pocket-LLM turns transformer concepts into working software. It bridges the gap between reading about tokenizers, autoregressive generation, checkpoints, and training loops and actually understanding how those pieces cooperate in practice. That foundation matters well beyond small models: engineers building LLM-powered systems make better decisions when they understand what the model is doing underneath the API surface.
